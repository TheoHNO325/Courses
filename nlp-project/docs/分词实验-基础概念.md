# 藏语分词实验：基础概念澄清

> 用途：回答"码位/Unicode 类别/`\p{L}`/tsheg/音节边界/格助词"等底层问题
> 纪律：✅ 已用本机 PowerShell 验证 ｜ ⚠️ 以教科书为准 ｜ ❓ 未确认

---

## 0. 先分清五个"层"——所有困惑的根源

文本在计算机里的层次，**从下到上**：

| 层 | 是什么 | 藏语例子 | 谁定义 |
|---|---|---|---|
| **① 码位**（code point） | Unicode 编号，写作 `U+XXXX` | `ཀ`=U+0F40，`ི`=U+0F72 | Unicode 标准（客观） |
| **② 字符 / 字素簇**（grapheme cluster） | 用户感知的"一个字" | `ཀི` = **2 个码位**，但人看是 1 个字 | Unicode 规则 |
| **③ 音节**（tsheg bar） | 藏文的书写/音系基本单位 | `བོད` = 3 个码位（བ+ོ+ད） | **tsheg 显式标记**（客观） |
| **④ 词** | 语言学单位 | `བོད་ཡིག` = 2 音节 = 1 词 | ❌ **无公认定义**（人为） |
| **⑤ 子词 / token** | 模型输入单元 | 由 BPE 决定 | 统计（频率驱动） |

**关键**：③ 是**客观且免费**的，④ 是**人为且有争议**的，⑤ 是**统计出来的**。
**本实验的核心动作**：用 ③（客观）去检验 ⑤（统计）有没有破坏 ③。

## 1. 码位 = Unicode 编码吗？

**是，但要注意区分三个东西**：

| 概念 | 含义 | 藏语 `ཀི`（"ki"） |
|---|---|---|
| **码位**（code point） | Unicode **分配给每个字符的编号** | 2 个：U+0F40（ཀ）、U+0F72（ི） |
| **字符 / 字素簇**（grapheme cluster） | 用户**感知为一个字**的单位 | 1 个（人眼看是"ki"这么一个字） |
| **字形**（glyph） | 字体**渲染出来的形状** | 一个渲染结果 |

所以：
- **"码位"是抽象编号**，不是"编码"这个动作，也不是"字形"。
- 通常说的"Unicode 编码"有两种意思：① **码位分配**（U+0F40 = ཀ）；② **存储编码**（UTF-8 / UTF-16，把码位变成字节）。UTF-8 里一个汉字 = 3 字节，一个藏文字母 = 2 字节。
- **一个"字"往往不止一个码位**：藏语尤其严重。

**藏语一个音节的码位数**（这是理解一切的关键）：

```
བསྒྲུབས   ← 一个音节（1 个 tsheg bar）
= བ + ྶ + ྒ + ྲ + ུ + བ + ས     ← 7 个码位
  基字  下置  下置  下置  元音  后置  再后置
```

结构可能是：**前缀 + 基字 + 上置 + 下置 + 元音 + 后置 + 再后置**，最多七八个码位。
→ **所以"一个音节"是一个多码位序列，BPE 完全可以在它中间下刀。**（汉语没这问题，见 §5）

**本机验证结果**（PowerShell 读 Unicode 类别，实测）：

| 字符 | 码位 | Unicode 类别 | 说明 |
|---|---|---|---|
| `ཀ` KA | U+0F40 | **OtherLetter (Lo)** | 辅音基字 |
| `ག` GA | U+0F42 | **OtherLetter (Lo)** | 辅音基字 |
| `ཱ` 元音 aa | U+0F71 | **NonSpacingMark (Mn)** | 元音符号 |
| `ི` 元音 i | U+0F72 | **NonSpacingMark (Mn)** | 元音符号 |
| `ེ` 元音 e | U+0F7A | **NonSpacingMark (Mn)** | 元音符号 |
| `ྵ` 下置辅音 | U+0FB5 | **NonSpacingMark (Mn)** | 下置辅音 |
| `་` **tsheg** | U+0F0B | **OtherPunctuation (Po)** | 音节分隔符 |
| `།` **shad** | U+0F0D | **OtherPunctuation (Po)** | 句/短语分隔符 |
| `A` | U+0041 | UppercaseLetter (Lu) | 参照 |
| `汉` | U+6C49 | OtherLetter (Lo) | 参照 |

## 2. Unicode 类别是什么？

**每个码位都有唯一一个"通用类别"（General Category）**，用两个字母缩写表示。这是 Unicode 给的**客观属性**，你不需要自己判断。

常用类别：

| 缩写 | 全名 | 含义 | 例子 |
|---|---|---|---|
| `Lu` | Uppercase_Letter | 大写字母 | `A` |
| `Ll` | Lowercase_Letter | 小写字母 | `a` |
| `Lo` | **Other_Letter** | 其他字母（无大小写） | `汉`、`ཀ` |
| `Lm` | Modifier_Letter | 修饰字母 | — |
| `Mn` | **NonSpacingMark** | **无空白组合记号**（叠加在别的字符上，不占独立宽度） | `ི`、`ེ`、`ྵ` |
| `Mc` | SpacingMark | 有空白组合记号 | 部分印度系文字元音 |
| `Po` | OtherPunctuation | 其他标点 | `་`、`།` |
| `Nd` | Decimal_Number | 十进制数字 | `0` |

正则里的 `\p{...}` 就是"按 Unicode 属性匹配"（`\p` = property）：

- **`\p{L}`** = 所有以 `L` 开头的类别 = `Lu` + `Ll` + `Lt` + `Lm` + `Lo`
- **`\p{M}`** = 所有以 `M` 开头的类别 = `Mn` + `Mc` + `Me`
- 参考：[Unicode TR18（正则表达式）](http://www.unicode.org/reports/tr18/tr18-22.html)

**所以"是否 `\p{L}`"的意思就是：这个码位的类别属不属于"字母"？**

- `ཀ`（Lo）→ ✅ 属于 `\p{L}`
- `ི`（Mn）→ ❌ **不属于** `\p{L}`，它属于 `\p{M}`（记号）

## 3. 所以 GPT-2 的正则会切开藏语——是的，而且是"结构性"的

GPT-2 预分词正则里的 `\p{L}+` 意思是"**一串字母**算一个块"。
它对藏语的行为：

```
བོད (bod, "藏")   = བ(Lo) + ོ(Mn) + ད(Lo)
                      ↓ \p{L}+ 只能吃字母，吃不到 Mn
预分词结果：  [བ] [ོ] [ད]     ← 3 个块，本该是 1 个音节
```

```
ཡིག (yig, "文")  = ཡ(Lo) + ི(Mn) + ག(Lo)
预分词结果：  [ཡ] [ི] [ག]
```

**关键机制**：BPE 的合并**只在块内进行**。`བ` 和 `ོ` 被分到不同块 → **无论训多少轮 merge，它们永远无法合并**。

→ 所以藏语的 fertility 被钉在"**1 token ≈ 1 码位**"的下界上，**这与 BPE 学得好不好无关**。

### ⭐ 内建对照组（这是本实验最漂亮的地方）

**藏语固有元音 a 不写元音符号**（这是藏文正字法的特点）。所以：

| 音节 | 码位 | 含元音符号？ | 会被 `\p{L}+` 切碎？ |
|---|---|---|---|
| `ད` (da) | 1 个（ད） | ❌ 无 | ✅ **不受损**（整块是 Lo） |
| `དི` (di) | 2 个（ད+ི） | ✅ 有 | ❌ **受损**（被切成两块） |

**同一份语料里天然存在这两组。** 任何完整率差异都只能归因于那条正则，而不是"藏语就是难"。
**这就是"语言内部的控制实验"**，比跨语言比较干净得多。

### 修复方案（就是这一行）

```python
# 原样（GPT-2）
PAT = r"""...| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""

# 修正：把组合记号并入"词"
PAT = r"""...| ?[\p{L}\p{M}]+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""
                     ^^^^^^^^^^^
```

> ⚠️ **准确说法**：改正则是**必要条件，不是充分条件**。
> 改完之后 BPE **才有机会**学到"ཀི 是一个单元"；能不能真学到，还取决于语料量与词表大小。
> **实验的价值正好在于测出"机会给了之后，BPE 到底学到了多少"**——这也正是为什么需要 §3 的内建对照组。

## 4. 汉语能用 BPE 吗？jieba 到底是干什么的？

### 4.1 能，而且所有 LLM 都在这么干

GPT-2 / Llama / Qwen 的 tokenizer **都是 BPE 系**，都对中文做子词切分。

但 **GPT-2 对中文很差**：UTF-8 里一个汉字 = **3 字节**，byte-level BPE 只能从字节开始合并 → **一个汉字常常占 2–3 个 token**。这就是著名的"中文 fertility 问题"。后来 Qwen 等专门扩了中文词表才改善。

### 4.2 jieba 不是给 LLM 用的

**jieba 和 BPE 不是同类工具，它们解决的是不同问题：**

| | **jieba（分词器）** | **BPE（子词切分器）** |
|---|---|---|
| 输入 → 输出 | 句子 → **词** | 字符/字节序列 → **子词** |
| 依据 | **词典 + 统计 + 标注规范** | **频率合并**（压缩驱动） |
| 方向 | **自上而下**（拿词典去匹配句子） | **自下而上**（从字符往上合并） |
| 有"正确性"吗 | ✅ 有（有金标、讲准确率） | ❌ 没有（只讲效率、覆盖率） |
| 服务谁 | **传统 NLP**：NER、关键词抽取、文本分类、搜索索引、句法分析 | **语言模型**：需要一个固定大小的词表 |

**关键**：**LLM 不需要"词"。** 它只需要"固定大小词表 + 尽量短的序列"。所以 LLM 用 BPE，不用 jieba。
反过来，**jieba 是从"需要词"的传统任务时代来的**——那些任务（词性标注、依存分析、检索）的输入单位必须是词。

### 4.3 汉语"应该怎么分词"——取决于目的

| 目的 | 用什么 | 输出单位 |
|---|---|---|
| 喂给 LLM | **不用分词**，用设计良好的 BPE（如 Qwen） | 子词 |
| 做 NER / 句法 / 检索 | jieba / pkuseg / LTP | 词 |
| 做评测 | 需要一个**标准** | 词 |

⚠️ **而且汉语也有多套分词标准**（PKU / MSR / CTB / CityU 等），**不同标准切法不一致**——`南京市长江大桥` 各家切得不一样。

> ⭐ **这个平行非常重要**：**汉语的"多套分词标准不一致"与藏语的"词无公认定义"是同构问题。**
> 两者都说明：**"词"这个层是人为的、有争议的**；而**"音节"这个层在两种语言里都是客观的**（见 §5）。
> 这也正是为什么本实验**把主分母选在音节层而不是词层**。

### 4.4 三层流程对比（汉语 vs 藏语）

```
汉语：  汉字序列 ──[分词:难,多标准]──→ 词 ──[BPE:统计]──→ 子词 token
藏语：  码位序列 ──[tsheg 切音节:免费]──→ 音节 ──[分词:难,无标准]──→ 词 ──[BPE]──→ 子词
                  ↑
        汉语没有这一层；藏语有，而且会被 \p{L}+ 破坏
```

## 5. tsheg 是什么？"音节边界"是什么意思？

### 5.1 tsheg

**tsheg = `་` = U+0F0B = OtherPunctuation（标点类字符）**

作用：**标示一个音节的结束**。

- 它**不是空格**（不是词分隔符）
- 它**不是标点**（虽然 Unicode 类别是标点）
- 它是**音节分隔符**——藏文正字法用它把音节一个个隔开

```
བོད་ཡིག
 = བོད | ཡིག      ← tsheg 分隔出 2 个音节
   (bod)  (yig)     "藏文"
```

另外还有 **shad `།` = U+0F0D**，标示**句/短语结束**（更高级的分隔）。

### 5.2 "音节边界"= tsheg 的位置（**免费的！**）

**测"音节完整率"完全不需要任何标注**：

```python
syllables = text.split('\u0F0B')   # 就这一行
```

因为 tsheg **显式标出了音节边界**。

### 5.3 三种语言的"音节边界"对比（这是实验独特性的技术根据）

| | 音节边界 | 免费吗 | 音节=几个码位 | BPE 能切碎它吗 |
|---|---|---|---|---|
| **英语** | 要靠读音判断 | ❌ **不免费**（拼写不反映音节） | 多个字母 | ✅ 能 |
| **汉语** | = 字符边界（1 字 = 1 音节） | ✅ 免费 | ⭐ **1 个码位** | ❌ **不可能** |
| **藏语** | = tsheg 的位置 | ✅ **免费** | ⭐ **多个码位** | ✅ **能** |

**这张表就是全部关键**：

- **汉语**：音节 = 单码位 → BPE **没法把它切一半** → **"音节完整率"在汉语上恒等于 1，这个指标没意义**
- **英语**：音节边界不免费 → 要先做音节切分才能测，麻烦
- **藏语**：音节边界**免费**，且音节**多码位**→ **这个指标只有在藏语（及类似附标文字）上才既免费又有意义，而且真的会被破坏**

> ⚠️ **噪声说明**：UGC 语料里 tsheg 会**省略 / 重复 / 错插**（[ACM 10.1145/3807246](https://dl.acm.org/doi/full/10.1145/3807246.3807333)），所以先要清洗（这本身就是 RQ2 的素材）。规范语料（佛典、司法）上 tsheg 可靠。

## 6. 格助词（case particle）是什么？

### 6.1 用类比引入

表达"谁对谁做了什么"，三种策略：

| 语言 | 策略 | 例子 |
|---|---|---|
| 英语 | **语序 + 介词** | `I eat rice`（I 在前 = 施事） |
| 汉语 | **语序 + 介词** | `我吃饭`（我在前 = 施事） |
| 日语 | **助词** | `私はご飯を食べる`（は=主题，を=宾格） |
| **藏语** | ⭐ **助词** | 见下 |

**藏语的格助词 ≈ 日语的「は / が / を / に / で」**：
**跟在名词后面，标记这个名词在句子里扮演什么角色。**

### 6.2 具体例子

```
བདག་གིས་ཆོས་ཉན།        = 我听法
 བདག      = 我
 གིས      = 作格助词  → 标记"我"是【及物动词的施事】
 ཆོས      = 法
 ཉན       = 听
```

```
བདག་གི་ཆོས།           = 我的法
 བདག      = 我
 གི       = 属格助词  → 标记【领属】
 ཆོས      = 法
```

**同一个名词 `བདག`（我），后面跟不同助词 → 完全不同的语法角色。**

### 6.3 助词清单（主要形式）

| 格 | 主要形式 | 功能 | 类比 |
|---|---|---|---|
| 作格 / 工具格 | `གིས / ཀྱིས / གྱིས / ས` | 及物动词的施事；工具 | 日语 が |
| 属格 | `གི / ཀྱི / གྱི / འི` | 领属 | 汉语"的"、英语 `of` / `'s` |
| 向格 / 处格 | `ལ` | 与格、方位 | 汉语"给 / 在"、日语 に |
| 从格 | `ལས / ནས` | 来源；**比较句的基准** | 汉语"从 / 比"、英语 `from` / `than` |
| 随同格 | `དང` | 与、和 | 汉语"和" |

> ⚠️ 各变体的**精确分布规则**（哪个韵尾后用哪个）以教科书为准（Bialek《A Textbook in Classical Tibetan》等）。此处只用来说明"**存在音系条件变体**"这个事实。

### 6.4 "音系条件变体"是什么意思

同一个格（例如属格）有 **4 个书写形式**：`ཀྱི / གྱི / གི / འི`。
**选哪个，取决于前一个音节末尾的音（韵尾）。**

这就像英语复数：

| 英语 | 选择的依据 |
|---|---|
| `cats`（清辅音后加 `-s`） | 依读音 |
| `boxes`（咝音后加 `-es`） | 依读音 |

### 6.5 ⭐ 回答你的问题："解决的是音的问题还是写出来的不同变位？"

**两者都是，但要分两层：**

| 层 | 答案 |
|---|---|
| **助词本身** | ✅ **是"写出来的"**——它是**独立的音节**，看得见、摸得着，不是重音/声调变化 |
| **用哪个变体** | ✅ **是"音"决定的**——选择规则依据**前一个音节的读音（韵尾）** |

→ 准确说法：**"变体是书写差异，但变体的选择规则是音系规则。"**

### 6.6 和英语对比——为什么这对 tokenizer 特别致命

| | 英语 `-s` | 藏语属格助词 |
|---|---|---|
| 形式 | **粘在词尾的字母** | **独立音节** |
| 书写 | `cats`（是**一个词**） | `བདག་གི`（**两个音节**，中间有 tsheg） |
| 变体选择 | 依读音 | 依读音 |

**后果**：

- 英语里 `cats` / `boxes` 的差异在**词尾字母**上 → BPE 切出 `cat`+`s` / `box`+`es` → **至少词干是共享的**，模型能看到规律
- 藏语里 `གི` / `ཀྱི` / `གྱི` / `འི` 是**四个完全不同的音节**，**没有共享的部分**，而且**每个变体自己还可能被 `\p{L}+` 切碎**
- 所以模型看到的是 4 个（或更多）**毫无形式关联**的东西 → 只能**逐个死记**"这个形式在这出现、那个形式在那出现" → **学不到"这是同一个格"**

> **低资源下这直接致命**：数据本来就不够死记，如果再让形态系统在表示层就散架，模型几乎不可能学会这条语法。

### 6.7 "格助词变体一致性"怎么算（纯计数，不需要人）

1. **找出现**：在语料（或现成的藏语形态/词性标注语料，如 [ACTib](https://zenodo.org/records/3951486)）中定位格助词的出现
2. **统计映射分裂度**：变体集合 → token 序列集合，例如用

   ```
   分裂度 = （出现过的不同 token 表示数量） / （格助词变体数量）
   ```

| 情况 | 比值 | 含义 |
|---|---|---|
| 理想 | 4 变体 → 1 种 token 表示 → **0.25** | tokenizer 让模型有机会学会"这是一个格" |
| 一般 | 4 变体 → 4 种 → **1.0** | 每变体各是一个 token，模型要学 4 件事 |
| 最坏 | 4 变体 → 8 种 → **2.0** | 每变体自己还被切碎，模型只能死记 |

**这个指标的价值**：它把「**分词质量**」和「**下游任务难度**」直接连起来了——而且是纯字符串统计，不需要训练、不需要人评。

## 7. 三个指标的定位（一句话各一条）

| 指标 | 测什么 | 一句话 |
|---|---|---|
| **① fertility** | **效率** | 同样内容，模型要读多少 token？（关系到算力、上下文、成本） |
| **② 音节完整率** | **正确性** | tokenizer 有没有把语言的基本单位（tsheg bar）切碎？ |
| **③ 格助词变体一致性** | **可学性** | tokenizer 有没有让模型"有可能"学会格这个语法范畴？ |

**加下游**：④ 用同一份数据后训练翻译，chrF++ 是否提升 → 验证"结构破坏"真的有下游代价。

### 完整论证链

```
改一行预分词正则（\p{L}+ → [\p{L}\p{M}]+）
   ↓ ① 效率改善？（省 token 吗）
   ↓ ② 正确性改善？（不再切碎音节了吗）— 用【含/不含元音符号】内建对照组归因
   ↓ ③ 可学性改善？（格助词变体更一致了吗）
   ↓ ④ 下游：后训练翻译 chrF++ 是否提升？
```
